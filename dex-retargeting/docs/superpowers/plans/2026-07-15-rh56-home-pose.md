# RH56DFTP Home Pose Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a guarded, smooth RH56DFTP storage pose and a workspace-level `../scripts/go_home.sh` command that invokes it through the running Viewer.

**Architecture:** The existing controller owns the complete move through a new `HOMING` state, using measured-position seeding and the current adaptive motion profile. FastAPI exposes one protected no-body transition; the shell command calls that API and polls health without opening Modbus itself.

**Tech Stack:** Python 3.11, NumPy, FastAPI, pytest, Bash, uv

## Global Constraints

- Home target: `[120, 120, 120, 120, 180, 480]` in RH56 six-channel order.
- Home starts only from connected `DISARMED` and does not require vision tracking.
- Motion uses the existing 30 Hz profile and one controller-owned Modbus writer.
- E-STOP interrupts home; Modbus failure or 20-second timeout enters `FAULT`.
- The shell client waits at most 25 seconds and never connects to Modbus.
- Automated verification must not command the physical hand.
